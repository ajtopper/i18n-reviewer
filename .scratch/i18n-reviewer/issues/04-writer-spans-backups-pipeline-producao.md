# 04: Writer cirúrgico por spans, backups agrupados e pipeline Enviar para Produção / Restaurar

**What to build:** O usuário publica suas traduções nos arquivos do módulo clicando em **Enviar para Produção** e pode reverter qualquer envio via **Restaurar Backup**. O writer cirúrgico reescreve apenas os spans modificados no texto original (garantindo round-trip byte a byte quando nada muda e diff mínimo no Git quando há edições, inserções ou remoções de órfãs). O pipeline pré-produção permite selecionar por checkbox quais idiomas modificados publicar, bloqueia arquivos com conflito ou erro estrutural, valida o payload em memória (`json.loads` + simulação `expandObject` + conferência do diff), gera um lote de backup agrupado em `%APPDATA%` e grava cada arquivo via `.tmp` + `os.replace` com retries para locks do OneDrive.

**Blocked by:** 03: Persistência .i18nproj, recuperação de crash e sincronização externa (merge 3-vias)

**Status:** ready-for-agent

- [ ] O writer por spans preserva byte a byte qualquer arquivo sem alterações e, nos arquivos editados, substitui apenas os spans dos valores modificados (preservando BOM, `CRLF`/`LF`, newline final, indentação, linhas em branco, objetos inline, separadores `"k" : "v"` e escapes das linhas não tocadas; usa `ensure_ascii=True` nos novos valores apenas se o arquivo destino inteiro escapar todos os não-ASCII).
- [ ] Em chaves duplicadas no mesmo arquivo, o writer edita o span da última ocorrência (a que vence no Foundry) sem apagar a ocorrência antiga sozinho.
- [ ] Chaves `missing` que receberam tradução são inseridas na posição relativa da base (após o vizinho/ancestral anterior da base presente no destino, no arquivo-espelho ou principal configurado), seguindo o estilo do próprio arquivo de destino (plano no plano, aninhado no aninhado criando objetos intermediários mínimos, e em arquivo misto entrando no objeto pai se existir ou seguindo o estilo do bloco/vizinho), com indentação e EOL do destino.
- [ ] Chaves órfãs marcadas para remoção têm o par e a vírgula adjacente removidos cirurgicamente, podando objetos pai que ficarem vazios após a remoção.
- [ ] O diálogo **Enviar para Produção** lista os arquivos com alterações pendentes (`dirty`) com checkboxes (permitindo publicar apenas os idiomas selecionados), revalida o SHA-256 no disco (interrompendo para o merge 3-vias se mudou), bloqueia arquivos com conflitos pendentes ou erros estruturais/fatais e agrupa numa confirmação única os avisos não-bloqueantes (chaves duplicadas, células `dirty` ainda `unreviewed`/`stale` e lista de órfãs a remover).
- [ ] Antes de tocar no disco, valida o payload gerado em memória com `json.loads` estrito, simula o `expandObject` do Foundry (garantindo que nenhuma edição/inserção introduziu folha-antes-de-ramo ou sobrescrita estrutural) e confere que o mapa resultante bate com as alterações planejadas.
- [ ] Cria lote de backup agrupado `YYYY-MM-DD_HHMMSS_NNN/` em `%APPDATA%\i18n-reviewer\backups\<project_id>\` com `manifest.json` (`publish`, hashes, caminhos) e cópia `.bak` apenas dos arquivos que serão gravados, aplicando retenção automática dos últimos 30 lotes (configurável em `settings.json`).
- [ ] Grava cada arquivo via `<arquivo>.tmp` no mesmo diretório do destino + `os.replace` com até 5 tentativas em backoff curto (`100–500 ms`) para locks do OneDrive/antivírus; em caso de falha parcial após os retries, interrompe os arquivos restantes e oferece rollback imediato do lote recém-gravado ou manter os já publicados (atualizando snapshots/`dirty` no `.i18nproj` apenas do que foi gravado e preservando `review_status`).
- [ ] O diálogo **Restaurar Backup** permite excluir lotes manualmente ou restaurar um lote inteiro / um arquivo individual: valida o `.bak`, cria antes um lote automático `pre-restore` do estado atual em produção, grava via `.tmp` + `os.replace` e pergunta se o usuário quer sincronizar via merge 3-vias (mantendo rascunhos locais) ou descartar também os rascunhos locais dos arquivos restaurados (voltando células `reviewed` alteradas para `unreviewed`).
- [ ] Testes `pytest` + `pytest-qt` cobrindo round-trip byte a byte, diff mínimo em arquivos não-canônicos, inserção relativa (plano, aninhado, misto), poda de pais ao remover órfãs, simulação de `PermissionError` (retries + falha parcial + rollback) e restauração com `pre-restore`.
